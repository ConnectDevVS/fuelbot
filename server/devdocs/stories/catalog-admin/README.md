# Admin catalog API — story set (Milestone S3)

Everything a dashboard needs to run a tenant's catalog without editing JSON:
tenants, the product library, machines (registered with a server-generated
id), each machine's menu and bases, and (platform only) maintenance and
unregistered machines. Every write is checked against the role table,
validated against the app's rules for every affected machine, versioned and
audited.

- Plan: [server-plan.md](../../plans/server-plan.md) §2.6 (ids), §3.2
  (config rules), §4.1, §4.4 (tenants, products, machines), §4.5 (status),
  §4.7 (roles, prices, platform-only data), §6 S3.
- Builds on: S1 (models, `services/catalog.js`), S2 (sessions, `rbac.js`,
  audit, pages).
- Conventions: [server/CLAUDE.md](../../../CLAUDE.md).

## Decisions

Product owner (2026-09-27, plan decision log): machine ids are generated by
the server, 8 characters from `A–Z0–9`.

Made while writing this set:

1. **Id generation:** `crypto.randomInt` over the 36 characters; insert, and
   on a duplicate key try a new id (36⁸ ≈ 2.8 × 10¹² ids, so a retry is
   practically never needed). The dev seed pins **`DEV00001`** so
   `dev_setup.gd` can default to it; nothing else chooses an id.
2. **Optimistic locking is required on versioned writes.** Product writes
   send `If-Match: <rev>`, machine writes `If-Match: <menu_version>`. Missing →
   **428 `if_match_required`**; stale → **409 `version_conflict`** with
   `details.current`. Maintenance is the exception (a switch, and urgent).
3. **A new machine is "not configured"** until its menu has a product. Its
   empty menu is allowed (and skipped by the config check), and
   `GET /fuelbot/config` answers **409 `machine_not_configured`**, which the
   app treats like offline (it keeps its cache or bundled catalog). Once
   configured, a menu can't be emptied again (the app's own rule: "flavors
   must be a non-empty array").
4. **Raw-body checks before Mongoose** (`catalog/input.js`): unknown fields
   and wrong types are **400 `invalid_body`** with `details: [{field,
   error}]`. The app's rules on the resulting config(s) are **422
   `invalid_config`** (S1). Prices are whole rupees.
5. **Price rule:** an operator's request that *changes* a price (a product's
   `actual_price`/`offer_price`, a menu item's `price`, or a copy that would
   change effective prices) is **403 `forbidden_field`**, and nothing is
   saved. Unchanged values are fine.
6. **Products are archived, never deleted.** Archiving a product that's on
   any menu is **409 `product_in_use`**. `image_url` isn't accepted here; it
   comes from the upload endpoint (S5). `image` (a bundled `res://` path) is.
7. **Product list:** each product lists the machines whose menu uses it,
   limited to the machines the caller may see.
8. **Maintenance** (`maintenance:write`, platform only): switching it on sets
   `flagged_by` (the user's name, else email) and `flagged_at` (now);
   switching it off clears both. It bumps `menu_version` (it's part of the
   config body).
9. **Machine status** (plan §4.5) is computed on read. `today` (sales) comes
   with the read APIs in S6.
10. **Branding changes** bump the tenant's `catalog_version` (they're in
    every machine's config).
11. **Audit** every write, with only the changed fields.
